# Nexus Speed Dial

Nexus is a local-first visual speed dial and workspace library for saved sites, projects, tags, notes, browser sessions, and bookmark imports.

## Run locally

```bash
npm ci
npm run dev
```

Vite serves the app on `http://localhost:5173` by default. The app stores sites, projects, sessions, history, and UI settings in browser local storage.

## Quality checks

```bash
npm run test       # unit tests
npm run build      # typecheck and production build
npm run qa:unit    # tests plus build
npm run qa:e2e     # Playwright app-shell checks when Chromium is installed
```

The repository currently has unit coverage for the main import, backup, settings, tile, browser bridge, and workspace flows. Real browser screenshot validation requires a Chromium runtime.

## Browser extension

`extension/` contains the Manifest V3 Nexus Workspace Bridge. It requests open tabs only after an explicit action in **Settings → Data → Connect browser** and requires the `tabs` permission.

- `extension/manifest.json` is the production manifest and allows only the published GitHub Pages origin.
- `extension/manifest.dev.json` is the development manifest for localhost and `127.0.0.1`.

For local extension development, load a separate copy of the extension with `manifest.dev.json` copied over `manifest.json`; do not use the development manifest for a production installation. Full protocol and installation notes are in [`extension/README.md`](extension/README.md).

## Data and privacy

Nexus is local-first: there is no application sync service. JSON backup and browser bookmark export/import are explicit user actions. The default site icon is rendered locally from the saved site record. Optional remote metadata lookup is gated by the local-storage privacy setting. Screenshot preview mode may use a remote screenshot provider when a persisted preview URL is available or generated by the site form.

### What leaves the machine when a tab opens

Measured by intercepting requests in a browser against the demo set, not estimated:

| Destination | Requests | Why |
|---|---|---|
| The saved sites themselves | one per site that has **no** mark in the bundled set | the icon fallback, `apple-touch-icon.png` first |
| `api.open-meteo.com` | at most one per 30 minutes, shared across tabs | the dock forecast, only while the weather widget is on |

Nothing else. Brand marks and both typefaces are served from the build, so a
site whose logo ships with the app never learns that a tab was opened. The
forecast is cached under `nexus-weather`, so opening twenty tabs makes one
request, not twenty. Both properties are locked by checks in
`e2e/app-shell.spec.ts` that were also run against the previous code to confirm
they fail there.

## Product areas

- **Speed Dial** — visual site tiles, favorites, sorting, selection, previews, and keyboard access.
- **Library** — search across title, domain, description, notes, and tags.
- **Projects** — projects, nested workspaces, site assignment, and browser sessions.
- **Tags and Notes** — organization and personal context around saved sites.
- **Data** — versioned backup restore, Netscape/HTML bookmark import/export, browser-tab import, deduplication, and destructive-data cleanup.

## Publishing a preview

`.github/workflows/pages.yml` builds the app and deploys it to GitHub Pages at

```text
https://loftfull.github.io/nexus-speed-dial/
```

It runs on manual dispatch only, because `actions/deploy-pages` fails until the
repository selects **Settings → Pages → Source: GitHub Actions**. Enabling that
is a one-time step the repository owner has to take; a Pages site is publicly
reachable, so the decision is theirs, not the workflow's. Once the source is
set, run the workflow from the Actions tab — or add a `push` trigger on the
working branch and the address will refresh itself.

`vite.config.ts` already switches `base` to `/nexus-speed-dial/` whenever
`GITHUB_ACTIONS` is present, which is exactly the subdirectory Pages serves.
Verified by serving the built `dist` at that path: tiles, brand marks, both
typefaces and the photo wallpaper all resolve with no 404.
