# Оформление Nexus Speed Dial: окончательный вариант

Зафиксировано 19 сентября 2026 на коммите `df6bc97`. Эталоны вида приняты
в `ae9b058`, проверка `Nexus QA` на этом состоянии зелёная целиком.

## Токены

Всё оформление собирается из переменных в `:root` (`src/app/theme.css`).
Значения по месту запрещены: `npm run scale` (он же внутри `npm run qa:unit`)
падает на любом числе вне шкалы.

**Кегль** — шесть ступеней и два размера часов:

| Токен | Значение | Где |
|---|---|---|
| `--nx-fs-1` | 11px | метки капсом, счётчики, подписи под образцами |
| `--nx-fs-2` | 12px | вторая строка, вспомогательный текст |
| `--nx-fs-3` | 13px | основной мелкий текст, названия плиток, кнопки |
| `--nx-fs-4` | 14px | вкладки категорий, поля форм |
| `--nx-fs-5` | 16px | подзаголовки, поле палитры, компактный заголовок |
| `--nx-fs-6` | 21px | заголовки разделов, монограмма знака |
| `--nx-fs-clock` / `-lg` | 46 / 54px | часы в боковом окне |

**Насыщенность** — три: 400 (текст), 600 (кнопки, вкладки, названия),
700 (заголовки, счётчики, метки капсом).

**Радиус** — четыре ступени и две формы: `--nx-r-xs` 4px (миниатюрные
элементы), `--nx-r-sm` 10px (кнопки-иконки, ячейки календаря),
`--nx-r-md` 14px (карточки, поля, чипы), `--nx-r-lg` 20px (окна, диалоги,
плитка по умолчанию), плюс `50%` и `999px`. Радиус плитки и знака сайта
остаётся за пользователем — это настройка, а не шкала.

**Цвет** — один набор на тему: `--nx-canvas`, `--nx-surface`, `--nx-sunken`,
`--nx-line`, `--nx-text`, `--nx-muted`, `--nx-accent`, `--nx-accent-soft`.
Тёмная тема переопределяет только их.

Неона и свечений в оформлении нет — этого сторож по-прежнему не пускает.
Стекло и мягкий рельеф вернулись как **готовые виды по выбору пользователя**
(`docs/design-styles.md`): вид по умолчанию остаётся плотным, без размытия
и слоя состояния.

## Поверхности

* **Боковое окно** — проводник «Проект → Категория → Группа», часы с погодой
  внизу; на узком экране его нет, вместо него лист разделов.
* **Верх главной** — кнопка проекта и вкладки категорий. Органов выбора вида
  здесь нет: вид сетки, сортировка и раскладка узкого экрана живут в
  настройках, в разделе «Плитки». Над сеткой — полоса избранного, одинаковая
  в любом проекте.
* **Сетка** — размер плитки идёт от окна, число колонок можно задать вручную;
  сетка это одна остановка табуляции, внутри фокус водят стрелки.
* **Палитра `Ctrl/⌘ K`** — единственное окно поиска, у каждой строки своя
  иконка и, где есть, горячая клавиша.
* **Настройки** — рельс разделов слева и одна открытая страница справа.
  Число столбцов в группе выбирается так, чтобы нижний ряд был полным: три
  по умолчанию, два для карточки из двух или четырёх ячеек. Внутри ячейки
  три полосы фиксированной высоты, поэтому подписи в ряду стоят на одной
  линии. Каждый контрол доказан тестом «ни один контрол не остаётся без
  действия».
* **Диалоги** — одна карточка с заголовком, полями и парой кнопок.
* **Пустые состояния** — своя иконка, объяснение и кнопка следующего шага.

## Знак фокуса

Кнопки и ссылки получают обводку `2px` акцентом с отступом `2px`. Поля ввода
показывают фокус по-своему — акцентной рамкой и мягким кольцом, — поэтому
обводку не дублируют. Шапка палитры подчёркивается акцентом.

## Гарнитуры лежат рядом с приложением

Inter и Manrope грузились со шрифтового сервиса Google. Для страницы новой
вкладки это плохая сделка сразу по трём причинам:

* каждое открытие вкладки сообщало чужому серверу адрес и браузер
  пользователя — ровно то, от чего в проекте уже ушли фирменные знаки сайтов;
* внешний лист стилей стоял в шапке и задерживал первую отрисовку;
* вид приложения зависел от доступности сети: там, где сервис недоступен,
  страница рисовалась системной гарнитурой, и снимки экрана расходились с
  эталонами.

Теперь файлы раскладывает `scripts/build-fonts.mjs` из пакетов
`@fontsource/inter` и `@fontsource/manrope` — так же, как `npm run brands`
раскладывает знаки из `simple-icons`. Собранное не хранится в истории, а
лицензии SIL OFL 1.1 кладутся рядом с файлами.

Объявления `@font-face` несут `unicode-range`, поэтому браузер забирает
только встретившиеся наборы знаков. Замер на демонстрационном наборе: из
двадцати четырёх файлов грузятся шесть — три насыщенности Inter в латинице и
кириллице, 96 060 байт (93,8 КБ) по размеру файлов в сборке. Расширенные наборы и Manrope объявлены, но лежат без дела,
пока на экране не появится такое название или пока в настройках плитки не
выбрана вторая гарнитура. Это закреплено проверкой «гарнитуры лежат рядом с
приложением, а не на чужом сервере» в `e2e/app-shell.spec.ts`.

## Сохранение целиком или никак

Состояние лежит в десяти ключах `localStorage`, и писались они подряд. Когда
место кончалось на середине, часть ключей ложилась, часть нет: после
перезагрузки сайты могли оказаться записанными, а категории, в которых они
лежат, — прежними.

Половина сохранения хуже, чем его отсутствие: во втором случае пользователь
видит ровно то, что было, и ему честно сказано, что место кончилось. Поэтому
перед записью снимаются прежние значения, и первая же неудача откатывает
всё обратно. Сообщение о переполнении показывалось и раньше — оно осталось.

Проверка в `src/domain/appStore.test.ts` моделирует потолок по объёму, а не
по числу записей: девять ключей из десяти при повторном сохранении не
меняются и места не просят, так переполнение не наступает вовсе. И разрыв в
ней смоделирован честно — ранний ключ помещается, поздний нет. Первая
редакция проверки этого не делала: отказ случался на первом же ключе, рвать
было нечего, и она проходила даже без отката.

## Почему снимки нельзя сверить на месте

Эталоны снимаются только в CI, и это не прихоть. В песочнице разработки лежит
Chromium 141.0.7390.37 (ревизия 1194), а установленный Playwright ждёт ревизию
1243 — Chromium 153.0.8010.12. Двенадцать больших версий разницы дают
расхождение около одного процента точек кадра на тех же самых данных.

Это стоит помнить, прежде чем искать причину расхождения в самом приложении.
Гарнитуры, например, тут ни при чём: когда их перенесли со шрифтового сервиса
к себе, местное расхождение не исчезло, а проверка эталонов в CI прошла на
прежних снимках — то есть вид не изменился вовсе.

## Что проверяет CI

| Проверка | Что держит |
|---|---|
| `npm run scale` | шкала кегля, насыщенности и радиуса |
| `npm run test` | модель оформления, палитры, перемещения по сетке, границы материалов |
| `npm run qa:e2e` | бюджет мобильного хрома, клавиатура, пустые состояния, полоса избранного, «ни один контрол без действия», стекло/рельеф/Material на экране |
| `npm run test:visual` | семь эталонных снимков: главная светлая и тёмная, палитра, настройки, календарь, мобильные главная и настройки |

### Почему у снимков есть вторая проверка

Совпадение с эталоном доказывает только совпадение с эталоном. Мобильная
главная однажды была принята с монограммами вместо логотипов: указатель
фирменных знаков не успевал доехать к моменту съёмки, и неверный кадр стал
образцом, с которым потом всё сходилось.

Поэтому перед каждым снимком главной считается перепись марок — сколько их
всего, сколько встало фирменным знаком и сколько знак нашли, но картинку не
отрисовали. Ожидается ровно `{ total: 9, brand: 8, pending: 0 }`. Девятая
марка — «Яндекс»: в установленном наборе simple-icons остался только Yandex
Cloud, поэтому `ya.ru` показывает монограмму «Я», и это верное поведение.

То же самое проверяется на живом экране и на всех трёх ширинах тестом
«на плитках стоят фирменные знаки, а не буквы» в `e2e/app-shell.spec.ts`.
Защита проверена обрывом запроса к `brands/index.txt`: без указателя число
знаков падает с восьми до нуля, и обе проверки краснеют.
