# Какой вид проводника подходит Nexus Speed Dial

Дата: 18 сентября 2026. Документ фиксирует разбор вариантов и причину выбора,
чтобы следующее изменение бокового окна не начиналось с нуля.

## Ограничения, из которых исходим

1. Ширина бокового окна — 240/292/340 px (настройка «Боковое окно»), свёрнутое
   состояние — 76 px, только иконки.
2. Иерархия ровно трёхуровневая: Проект → Категория → Группа
   (`src/domain/types.ts`, `migrateHierarchy`).
3. Сейчас в первом запуске 6 проектов, 9 категорий, 5 групп (`src/domain/seed.ts`).
   Реальный пользователь легко доведёт это до десятков узлов.
4. Выбор проекта продублирован в верхней панели кнопкой-переключателем,
   поэтому боковое окно больше не единственный способ сменить проект.
5. Ниже 900 px боковое окно не показывается вовсе — там работает шторка «Разделы».

## Разобранные варианты

| Вариант | Что это | Почему не подходит / подходит |
| --- | --- | --- |
| **A. Полное дерево, все ветки раскрываются независимо** | то, что было до этой правки | При 6 раскрытых проектах список уезжает на 3–4 экрана прокрутки, и активная категория теряется из виду. Отступ третьего уровня съедает ширину: названия групп обрезались уже на 292 px. |
| **B. Колонки Миллера** (проект / категория / группа тремя столбцами) | как в macOS Finder | Нужно минимум 3×200 px. Не влезает ни в 340 px, ни тем более в свёрнутое окно. |
| **C. Drill-in с «хлебными крошками»** | один уровень за раз, назад по крошкам | Экономит место, но теряется обзор: не видно, какие ещё категории есть рядом. Для 3 уровней это лишний клик на каждое действие. |
| **D. Дерево с одиночным раскрытием** (single-expand accordion) | раскрыт ровно один проект и внутри него ровно одна категория | Держит список коротким при любом числе проектов, сохраняет обзор соседей, работает в 240 px, переносится на свёрнутое окно (там остаются иконки проектов). |
| **E. Плоский список избранных узлов + поиск** | без иерархии | Противоречит модели данных: группы внутри категорий перестают быть видимыми. |

## Выбран вариант D

Реализация в `src/app/App.tsx`:

- нажатие на проект делает его активным и раскрывает **только его**
  (`setOpenProjects(open => open.includes(id) ? [] : [id])`), повторное нажатие
  сворачивает ветку целиком;
- нажатие на категорию раскрывает **только её** внутри проекта;
- у каждого узла справа счётчик сайтов (`treeCounts`), чтобы пустые ветки
  были видны до раскрытия;
- у категорий и групп есть `title`, поэтому длинное имя читается во всплывающей
  подсказке, даже если строка обрезана.

## Цвет узла

Выделенный проект и выделенная категория получают не только подложку, но и
цветную иконку. Цвет берётся из `src/domain/nodeColor.ts`:

- проект — его собственное поле `color`, а если оно не hex, то цвет из палитры
  по хешу идентификатора;
- категория и группа — цвет палитры по хешу идентификатора (своего поля цвета
  у них в модели нет).

Цвет уходит в строку CSS-переменной `--nx-node`, а правила
`.nx-tree-row.on` в `src/app/theme.css` красят иконку, счётчик и подложку.
В свёрнутом окне активная иконка дополнительно обводится тем же цветом —
это единственный признак выбора, когда подписей не видно.
